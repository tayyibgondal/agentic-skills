Why

Most agents write code. Few do the work around it.

Scanning for leaked secrets, bumping CVEs, opening PRs against the right branch, cutting SemVer tags, rolling back on a bad release — that's where a senior engineer earns their keep. Encode it once, here.

Hard rules, every time

Every skill ships with a "never break" rules block. No reset to main, no force-push, no auto-merge on a rollback PR. The agent inherits the discipline.

One interactive prompt

Every skill is autonomous except ship-ready, which asks once before opening the PR. Everything else just runs.

Tool-agnostic

Each skill is a single SKILL.md with frontmatter. Drop it into .cursor/skills/, .claude/skills/, or wherever your agent looks.

The library

15 skills, four categories, one orchestrator.

Each card links to the underlying SKILL.md. Read one end-to-end and you'll see exactly what your agent will do.

Audits

catch it before ship
3 leaf skills + 1 orchestrator
secret-scan

Sweep the repo for leaked API keys, tokens, and credentials. Auto-extracts hits into env-var lookups.
dependency-audit

pip-audit + npm audit. Auto-bumps CRITICAL/HIGH CVEs; verifies the lockfile still resolves.
security-audit

SQL injection, CORS, schema validation, cookies, file uploads, eval/exec, path traversal, SSRF, XSS.
audit-all orchestrator

Runs the three above in the right order, with hard-stop gates between steps.

Hygiene

keep it healthy
3 leaf skills + 1 orchestrator
dead-code-sweep

ruff + eslint + vulture + ts-prune. Auto-removes unused imports/vars; flags unreferenced files for review.
lint-and-typecheck-fix

ruff --fix, mypy, eslint --fix, tsc --noEmit. Auto-fixes what tools can; categorizes the rest.
file-size-enforcer

Enforces a 700-line cap. Auto-splits 701-1000 line files; writes a proposed-split TODO for anything bigger.
hygiene-all orchestrator

Runs the three above. Dead code first (so file-size measurements are accurate), then lint, then split.

Git & Ship

land changes safely
4 skills
commit-chat-to-branch

Smallest skill in the system. Takes the chat's edits, branches from staging, commits — then stops.
review-and-ship-to-staging

Critical code review of every edited file, then branch → commit → PR → merge against staging.
promote-staging-to-main

Open a PR from staging → main and merge as a true merge commit. Pure release event, no code changes.
rollback-release

Roll back main to a previous tag via git revert on a PR (never git reset). Stops for human approval.

Releases

tag, notes, publish
2 skills
release-tag

Decides the next SemVer from conventional commits, creates an annotated tag, appends to release-notes.txt.
release-notes-gen

Renders a grouped Markdown changelog between two refs, publishes it as a GitHub Release.

Top-level

the whole pipeline, one command
1 orchestrator
ship-ready orchestrator

audit-all → hygiene-all → (asks once) → review-and-ship-to-staging. The single interactive prompt in the system.
Workflows

Pre-baked pipelines for the four moments that matter.

Daily, pre-ship, release, emergency. Pick the one that matches your situation and your agent runs the rest.

Daily small fix

A typo, a styling tweak, a one-line bug fix.

review-and-ship-to-staging

Pre-ship anything sensitive

Auth, billing, admin, schema changes.

ship-ready
 ├─ audit-all
 │   ├─ secret-scan
 │   ├─ dependency-audit
 │   └─ security-audit
 ├─ hygiene-all
 │   ├─ dead-code-sweep
 │   ├─ lint-and-typecheck-fix
 │   └─ file-size-enforcer
 ├─ (asks: ship? yes/no)
 └─ review-and-ship-to-staging

Release

Staging is stable; cut a production release.

promote-staging-to-main
   ↓
release-tag
   ↓
release-notes-gen

Emergency

Prod is unhappy; back it out without rewriting history.

rollback-release v<prev-tag>
